# PrankFX — исправленная версия

Проект готов к работе в VS Code. Ниже: что было сломано, что починено и как запустить.

---

## 1. Главная проблема: вход через новый Google-аккаунт

Симптом: аккаунт из списка заходит, «Использовать другой аккаунт» — нет.

Причин было **три**, и все три устранены.

### Причина A — код авторизации использовался дважды (главная, в коде)

В `app/auth/login.tsx` вызывался `Google.useIdTokenAuthRequest(...)`, а потом код
вручную менялся на токены через `AuthSession.AccessTokenRequest`.

На Android `useIdTokenAuthRequest` внутри expo-auth-session сводится к
`responseType = "code"`, и библиотека **сама** обменивает этот код в своём
`useEffect` (флаг `shouldAutoExchangeCode` по умолчанию включён). То есть один и
тот же `code` отправлялся в Google **два раза**.

Код авторизации OAuth — одноразовый. Второй обмен Google отклоняет с
`invalid_grant`. Кто из двух успеет первым — зависит от тайминга рендера, поэтому
вход «то работал, то нет»: уже авторизованный аккаунт возвращается из браузера
мгновенно, а новый аккаунт проходит ввод пароля и экран согласия и возвращается
намного позже — тайминг другой, и выигрывал уже другой запрос.

**Исправлено:** вся логика вынесена в `src/auth/useGoogleAuth.ts` с
`shouldAutoExchangeCode: false`. Библиотека код больше не трогает — обмен
происходит ровно один раз, в нашем коде.

### Причина B — ошибки Google проглатывались молча

Старый код:

```ts
if (result.type !== "success") {
  console.log("GOOGLE: authorization was not successful:", result.type);
  return;   // ← ни тоста, ни сообщения
}
```

Поэтому при любом отказе Google приложение просто «ничего не делало» и
пользователь оставался на экране входа без единого объяснения.

**Исправлено:** каждый вариант отказа (`access_denied`, `redirect_uri_mismatch`,
`invalid_client`, `admin_policy_enforced`, `invalid_grant`, …) превращается в
понятный текст на экране. Отмена пользователем по-прежнему молчит — это норма.

### Причина C — настройка Google Cloud Console (делается руками!)

Если экран согласия OAuth в статусе **Testing**, Google пускает **только** те
аккаунты, что добавлены в список тестовых. Все остальные получают
`access_denied`. Это ровно ваш случай: аккаунты из списка — ваши тестовые, любой
другой email отбивается.

Теперь приложение это прямо покажет. Чтобы починить:

1. https://console.cloud.google.com/ → выберите проект `917307607930`
2. **APIs & Services → OAuth consent screen** (в новом интерфейсе — **Audience**)
3. Либо:
   - **Testing:** добавьте нужные email в **Test users** (до 100 штук), либо
   - **Publish app → In production** — тогда войти сможет кто угодно
     (для scopes `openid/profile/email` проверка Google не требуется)
4. **APIs & Services → Credentials → Android client** — проверьте:
   - Package name: `com.prankfx.app`
   - SHA-1 — отпечаток того ключа, которым реально подписана установленная сборка

SHA-1 для debug-сборки (`npx expo run:android`):

```bash
cd frontend/android
./gradlew signingReport        # Windows: gradlew.bat signingReport
```

Возьмите SHA1 из блока `Variant: debug` и вставьте в Android OAuth client.
Изменения в консоли применяются несколько минут.

> Важно: в `android/app/build.gradle` release-сборка сейчас тоже подписана
> **debug**-ключом. Перед публикацией сделайте отдельный release keystore и
> добавьте его SHA-1 в Google Console отдельной записью.

## 2. Что ещё исправлено

### Авторизация и сессия

| Проблема | Было | Стало |
|---|---|---|
| Токен жил 60 минут, refresh-потока нет | Пользователя молча выкидывало на вход посреди работы | Токен живёт 30 дней (`ACCESS_TOKEN_EXPIRE_MINUTES`) |
| `refresh()` чистил токен при **любой** ошибке | Одна потерянная сеть = разлогин | Сессия сбрасывается только при 401/403; сеть → флаг `offline` |
| `/auth/me` дёргался даже без токена | Лишний 401 на каждом старте | Запрос уходит только при наличии токена |
| Google-верификация ловила только `ValueError` | `TransportError` → пустой 500 | Все ветки обработаны, в ответе читаемая причина |
| Часы телефона на пару секунд врут | `Token used too early` → отказ | `clock_skew_in_seconds=60` |
| Нет уникального индекса на email | Два быстрых входа = два аккаунта на один email | Уникальный индекс + обработка `DuplicateKeyError` |
| Google-вход не связывался с существующим аккаунтом | Профиль не обновлялся | Имя/аватар подтягиваются, аккаунт связывается |
| Вход паролем в Google-аккаунт | «Invalid email or password» | «Аккаунт создан через Google, используйте кнопку Google» |
| `passlib` 1.7.4 + `bcrypt` 4.1.3 | Известный конфликт, шумные трейсбеки | Прямой `bcrypt`, старые хеши совместимы |

### Навигация

- **`/collection` не открывался.** Условие в `_layout.tsx` было
  `!inTabs && !inCreate` — маршрут `collection` под него не подпадал, и нажатие
  на коллекцию мгновенно возвращало на Home. Теперь маршруты перечислены явно.
- Переход мог сработать до монтирования роутера — добавлена проверка
  `useRootNavigationState()`.
- Убрано повторное срабатывание одного и того же редиректа (мигание экрана).
- Пока проверяется сохранённая сессия, показывается лоадер, а не экран входа.

### Экономика FX

- Home проверял **`free_credits_remaining`** — легаси-поле, которое никто
  никогда не уменьшает. Пейволл не показывался, генерация падала с 402, а
  купленные FX при этом игнорировались. Теперь проверяется `fx_credits`.

### Сеть и сервер

- У `fetch` не было таймаута — мёртвый бэкенд вешал спиннер навсегда.
  Добавлен таймаут 60 с и внятное «сервер недоступен».
- Без `EXPO_PUBLIC_BACKEND_URL` собиралась строка `undefined/api`. Теперь
  сообщение прямо говорит, что создать и где.
- Ошибки валидации FastAPI (массив объектов) больше не сыплются в тост как JSON.
- CORS был прибит к `localhost:8081` — web-сборка и dev-client не работали.
  Теперь настраивается через `CORS_ORIGINS`.
- Было **два разных FastAPI-приложения** (`server.py` и `app/main.py`), причём в
  `server.py` не запускалась стартовая миграция. Теперь одно приложение.
- Добавлен `/api/health` — быстро проверить с телефона, что сервер и база живы.
- Gemini: клиент создавался при импорте (падение без ключа), использовался только
  новый `interactions` API. Теперь ленивая инициализация и fallback на
  `generate_content`.
- Startup больше не роняет сервер, если Mongo временно недоступна.

### Прочее

- Кнопка **Continue with Google** добавлена и на экран регистрации.
- Убрана платформенная обвязка Emergent (`scripts/cmd-guard*`, `preinstall`),
  которая мешала обычному `npm install` локально.
- `metro.config.js`: `maxWorkers` больше не зафиксирован на 2 — сборка быстрее.
- Добавлены `.env.example` для обеих частей и сгенерирован реальный `JWT_SECRET`.

## 3. Запуск

### Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# .env уже создан, JWT_SECRET сгенерирован.
# Впишите GEMINI_API_KEY и, если нужно, MONGO_URL.

uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

`--host 0.0.0.0` обязателен, иначе телефон не достучится.

Проверка: откройте `http://<IP-компьютера>:8000/api/health` — должно быть
`{"status":"ok","database":"connected", ...}`.

### Frontend

```bash
cd frontend
npm install

# ВАЖНО: впишите в frontend/.env реальный IP компьютера
# EXPO_PUBLIC_BACKEND_URL=http://192.168.1.42:8000

npx expo run:android
```

Телефон и компьютер должны быть в одной Wi-Fi сети. После правки `.env`
перезапускайте с очисткой кэша: `npx expo start -c`.

### Проверка типов

```bash
cd frontend && npx tsc --noEmit      # проходит без ошибок
```

## 4. Если Google-вход всё ещё не проходит

Теперь приложение показывает точную причину. Сопоставьте текст с таблицей:

| Сообщение | Что делать |
|---|---|
| `access_denied` | Экран согласия в Testing → добавьте email в Test users или опубликуйте приложение |
| `redirect_uri_mismatch` | Проверьте package name и SHA-1 в Android OAuth client |
| `invalid_client` | Не тот client id для платформы |
| `invalid_grant` | Код просрочен — просто повторите вход |
| `Token has wrong audience` | Добавьте client id в `GOOGLE_CLIENT_IDS` в `backend/.env` |
| `Cannot reach the server` | Не тот `EXPO_PUBLIC_BACKEND_URL`, или uvicorn запущен без `--host 0.0.0.0` |
| `admin_policy_enforced` | Аккаунт Google Workspace заблокирован политикой администратора |

Логи backend теперь пишут полный трейсбек по каждой неудачной проверке токена —
смотрите консоль uvicorn.
