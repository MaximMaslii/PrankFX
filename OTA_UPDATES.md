# PrankFX — обновления без магазина (DevOps)

После выхода в Google Play / App Store большинство изменений доходят до
пользователей **без новой версии в магазине**. Есть три уровня.

---

## 1. Только сервер — мгновенно, приложение не трогаем

Всё ниже меняется в `backend/.env` (или в коде бэкенда) и перезапуском сервера.
Пользователи видят это при следующем открытии приложения.

| Что | Где | Пример |
|---|---|---|
| Какая нейросеть оживляет фото | `SNAP_PHOTO_ENGINE` | `lucy` (сейчас, Lucy 2.5) или `pixverse` |
| Запасной движок, если основной упал | `SNAP_PHOTO_FALLBACK` | `true` |
| Модель Decart | `DECART_MODEL` | `lucy-2.5` |
| Цена видео в FX | `SNAP_FX_COST` | `10` |
| Новые видео-эффекты, их названия и описания на 3 языках, эмодзи, метка ХИТ/НОВОЕ | `backend/snap_effects.py` (`SNAP_EFFECTS` + `SNAP_COPY`) | добавил эффект → он сразу в приложении |
| Экран «Ведутся работы» | `APP_MAINTENANCE=true` + `APP_MAINTENANCE_MESSAGE_RU/EN/DE` | на время переезда сервера |
| Принудительное обновление из магазина | `APP_MIN_VERSION=1.1.0` | только после НАТИВНЫХ изменений (см. п. 3) |

Проверка: `https://ваш-домен/api/health` — поле `photo_engines` показывает,
какие движки готовы и в каком порядке пробуются.
`https://ваш-домен/api/app/config` — что сейчас получает приложение.

---

## 2. Over-the-air (EAS Update) — JS-код, экраны, тексты, картинки

Любые правки в `frontend/app`, `frontend/src`, переводы, дизайн, картинки —
публикуются одной командой, магазин не нужен.

### Один раз, до первой сборки для магазина

```bash
cd frontend
npx expo install expo-updates      # уже прописан в package.json — просто установит
npm install -g eas-cli
eas login
```

В `eas.json` замените `https://REPLACE-WITH-YOUR-DOMAIN` на реальный адрес
бэкенда в профилях `preview` и `production`. Затем соберите приложение **один
раз** (оно должно содержать expo-updates):

```bash
eas build --profile production --platform android
```

Уже настроено в проекте:
- `app.json` → `updates.url` (ваш projectId), `runtimeVersion: appVersion`,
  проверка обновлений при каждом запуске;
- `eas.json` → каналы `development` / `preview` / `production`;
- приложение ещё и проверяет обновления при возврате в него
  (`src/utils/otaUpdates.ts`), а применяет их при следующем запуске —
  никогда не посреди генерации;
- в Настройках внизу видно версию и id установленного обновления.

### Каждое обновление

```bash
cd frontend
npm run update:production -- "Новые эффекты и исправления"
# для тестовой сборки (APK preview):
npm run update:preview -- "Тест нового экрана"
```

Скрипт берёт адрес бэкенда из `eas.json` (а не из вашего `.env` с
192.168…) и не даст опубликовать, если там ещё REPLACE или локальный IP.

Откат, если что-то сломалось:

```bash
eas update:list --branch production
eas update:republish --group <id-предыдущего-обновления>
```

## 3. Когда всё-таки нужна новая версия в магазине

Только при **нативных** изменениях:
- добавили библиотеку с нативным кодом (камера, покупки, новый `expo-*` с нативной частью);
- новое разрешение в `app.json` (камера, микрофон…);
- обновление Expo SDK;
- смена иконки/сплэша/названия пакета.

Порядок:
1. Поднимите `"version"` в `frontend/app.json` (например `1.0.0` → `1.1.0`).
   OTA-обновления привязаны к версии, поэтому старые сборки не получат
   несовместимый код.
2. `eas build --profile production` → отправить в магазин.
3. Когда новая версия опубликована, при желании поставьте на сервере
   `APP_MIN_VERSION=1.1.0` — старые версии увидят экран «Пора обновиться».
