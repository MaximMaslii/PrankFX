## 1. Переменные окружения

### `backend/.env`

```
# RevenueCat
REVENUECAT_WEBHOOK_AUTH=<придумайте длинную случайную строку>
REVENUECAT_SECRET_KEY=<новый sk_... после отзыва старого>
PREMIUM_ENTITLEMENT_ID=premium

# Sign in with Apple — bundle id приложения
APPLE_CLIENT_IDS=com.prankfx.app

# Защита входа (значения по умолчанию, менять не обязательно)
AUTH_RATE_LIMIT_ATTEMPTS=10
AUTH_RATE_LIMIT_WINDOW_SECONDS=300
```

`REVENUECAT_WEBHOOK_AUTH` придумываете вы сами: ту же строку вписываете в
RevenueCat (шаг 3). Пока она пустая, вебхук отвечает 401 на всё — это
намеренно: открытый эндпоинт, начисляющий FX, был бы бесплатным краном.

Сгенерировать строку: `python -c "import secrets; print(secrets.token_urlsafe(32))"`

### `frontend/.env`

```
EXPO_PUBLIC_REVENUECAT_ANDROID_KEY=goog_...
EXPO_PUBLIC_REVENUECAT_IOS_KEY=appl_...
```

Это **публичные SDK-ключи** из RevenueCat → Project Settings → API keys →
App-specific keys. Они предназначены для клиента, их видно в бандле — это
нормально. Секретный `sk_...` в приложение не попадает никогда.

## 2. Товары в магазинах

### 2.1. Подписка — главный товар

Создайте **автопродлеваемую подписку** (auto-renewable subscription):

| Product ID | Период | FX | Цена в каталоге |
|---|---|---|---|
| `prankfx_weekly` | 1 неделя | 50 | $6.99 |

- **Google Play Console** → Monetise → Subscriptions → Create subscription.
  Base plan id — любой (например `weekly`); код игнорирует суффикс `:weekly`.
- **App Store Connect** → Features → Subscriptions → создайте группу
  «PrankFX Premium» и в ней подписку с этим product id.

Что даёт подписка (это уже в коде, менять ничего не нужно):

- 50 FX начисляются при первой оплате и **при каждом продлении**;
- `is_premium = true` → с видео снимается вотермарк;
- FX не сгорают — то, что не потратили за неделю, остаётся.

Важная деталь начисления: FX даются только на события `INITIAL_PURCHASE` и
`RENEWAL`, то есть когда реально прошли деньги. `UNCANCELLATION` (человек
передумал отменять) статус возвращает, но FX не начисляет — иначе можно было
бы отменять и возвращать подписку в цикле и получать по 50 FX за раз, заплатив
один.

И наоборот: `CANCELLATION` **не** отключает премиум. Это только отмена
автопродления; оплаченная неделя дорабатывает до конца, а премиум снимается по
`EXPIRATION`. Если этот вебхук потеряется, сервер всё равно снимет премиум сам
при следующем запросе `/api/auth/me` — по дате `premium_expires_at`.

### 2.2. FX-паки — докупка

Создайте **consumable** («расходуемые») товары с такими id — код сопоставляет их
с пакетами автоматически:

| Product ID | FX | Цена в каталоге |
|---|---|---|
| `fx_starter` | 5 | $0.99 |
| `fx_basic` | 15 | $2.49 |
| `fx_popular` | 40 | $6.99 |
| `fx_pro` | 100 | $14.99 |
| `fx_ultimate` | 250 | $34.99 |

Допускаются и написания `prankfx_fx_popular` или просто `popular` — и сервер, и
клиент нормализуют id одинаково. Суффикс Google `:base-plan` игнорируется.

- **Google Play Console** → Monetise → In-app products.
- **App Store Connect** → Features → In-App Purchases → Consumable.

Цены в приложении показываются те, что вернул магазин (в валюте пользователя);
цифры из нашего каталога — запасной вариант, если магазин недоступен.

## 3. RevenueCat

1. Project → Apps: подключите Play (service account JSON) и App Store (ASC key).
2. Products: импортируйте шесть товаров — подписку и пять паков.
3. Offerings: создайте offering `default` и положите в него **все шесть**.
   И экран пейволла, и магазин FX читают `offerings.current`; пейволл ищет в
   нём пакет с product id `prankfx_weekly`, магазин — остальные пять.
4. Entitlements: заведите entitlement с id `premium` (совпадает с
   `PREMIUM_ENTITLEMENT_ID`) и привяжите к нему подписку `prankfx_weekly`.
   Без этого «Восстановить покупки» не вернёт подписку — сервер спрашивает
   RevenueCat именно про этот entitlement.
5. **Integrations → Webhooks:**
   - URL: `https://<ваш-домен>/api/purchases/revenuecat`
   - Authorization header: та самая строка из `REVENUECAT_WEBHOOK_AUTH`
   - события: все (лишние сервер молча подтверждает).

Проверить связку можно кнопкой «Send test event» — в логах бэкенда появится
`RevenueCat test event received`, ответ 200.

## 4. Sign in with Apple

1. Apple Developer → Certificates, IDs & Profiles → Identifiers → ваш App ID →
   включить **Sign in with Apple**.
2. В `app.json` уже стоит `"usesAppleSignIn": true` — EAS добавит entitlement
   при сборке.
3. Кнопка появляется только на iOS и только если система её поддерживает;
   на Android её нет, и это правильно.

Что важно знать про Apple: имя пользователя приходит **только при первом
входе** и никогда не лежит в токене (приложение пересылает его отдельно), а
почта может быть скрытой вида `…@privaterelay.appleid.com`. Поэтому аккаунт
привязывается к `sub`, а не к почте — иначе каждый повторный вход создавал бы
нового пользователя.

## 5. Как это работает (чтобы понимать, где смотреть при проблемах)

```
Приложение: Purchases.purchasePackage()
    ↓ платёж проводит Google/Apple
RevenueCat: подтверждает чек
    ↓ POST /api/purchases/revenuecat  (Authorization: ваша строка)
Бэкенд: проверяет заголовок → пишет событие → начисляет FX
    ↓
Приложение: опрашивает баланс, показывает «+40 FX»
```

Приложение **никогда** не сообщает серверу, что было куплено. Клиент может
только начать покупку; баланс двигает вебхук. Всё, что мог бы утверждать
клиент, мог бы утверждать и злоумышленник.

Защита от двойного начисления: каждое событие RevenueCat пишется в коллекцию
`purchases` с уникальным индексом по `event_id`, плюс отдельная проверка перед
вставкой. RevenueCat повторяет доставку, пока не получит 2xx — повтор
безвреден.

Возврат денег (CANCELLATION с причиной от поддержки) снимает FX обратно, но
не ниже нуля: если пакет уже потрачен, убыток наш, а не отрицательный баланс у
пользователя.

Кнопка «Восстановить покупки» делает два шага: SDK перечитывает чек на
устройстве, затем сервер спрашивает RevenueCat, на что подписан аккаунт.
Восстанавливаются **подписки**; расходуемые FX не восстанавливаются — иначе
это был бы бесконечный источник кредитов.

## 6. Проверка без магазина

```bash
cd backend
pip install mongomock-motor
python tests_unit/manual_purchase_check.py
```

Скрипт поднимает приложение на поддельной базе и проверяет 16 вещей: что
вебхук без заголовка отвечает 401, что повтор события не начисляет дважды, что
возврат не уводит баланс в минус, что вход начинает отвечать 429. У меня всё
зелёное — полезно прогнать после любых правок в этой части.

## 7. Тестирование с реальными покупками

- **Android:** залейте сборку в internal testing, добавьте себя в License
  testers (Play Console → Setup → License testing) — тогда покупки бесплатны.
- **iOS:** создайте Sandbox tester в App Store Connect и войдите им в
  Settings → App Store → Sandbox Account.
- В RevenueCat события из песочницы помечаются `environment: SANDBOX` —
  сервер обрабатывает их так же, это ожидаемо для теста.

## 8. Гостевой режим

Приложение больше не показывает форму регистрации на старте. При первом
запуске оно само создаёт аккаунт (`POST /api/auth/guest`), привязанный к
случайному идентификатору установки из keychain устройства.

Что нужно знать:

- Аккаунт настоящий с первой секунды: у него есть `user_id`, свой баланс FX и
  своя история. Не хватает только способа войти в него с другого телефона.
- Бесплатный FX выдаётся **один раз на установку**, а не на запуск: повторный
  вызов с тем же device_id возвращает тот же аккаунт.
- Когда гость регистрируется или входит через Google/Apple, его аккаунт
  **повышается на месте** — `user_id` не меняется. Это важно именно для
  покупок: `app_user_id` в RevenueCat остаётся тем же, и оплаченное никуда не
  уезжает.
- Если он входит в аккаунт, который уже существует, повысить нечего: его
  фотографии и ролики переносятся в тот аккаунт, а пустой гостевой документ
  удаляется. **FX при этом не переносится** — иначе «создать гостя → войти →
  очистить приложение → повторить» было бы бесконечным источником бесплатных
  кредитов.
- Гость не может ничего купить. Кнопка покупки ведёт на регистрацию, потому
  что покупка под аккаунтом без входа теряется при переустановке, и доказать,
  что она была, человек не сможет.
- Выключается одним флагом: `GUEST_MODE_ENABLED=false` в `backend/.env`
  возвращает старое поведение со стеной регистрации.

Проверить: `/api/health` должен показывать `guest_mode: on`.

## 9. Не забыть перед релизом

- `ALLOW_MOCK_PURCHASES=false` в `backend/.env` (сейчас `true`; при старте
  сервер пишет предупреждение, а `/api/health` показывает `mock_purchases`).
- Проверить `/api/health`: `revenuecat_webhook: configured`,
  `apple_sign_in: configured`, `mock_purchases: off`.
- Отозвать засвеченные ключи: RevenueCat `sk_`, Decart, Gemini.
